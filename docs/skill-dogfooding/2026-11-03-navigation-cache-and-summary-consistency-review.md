## humanizer 수정 전후

40개 패턴을 문장부호·띄어쓰기·품사·어휘·구조·번역투 범주로 수동 점검했다. 기술 식별자와 불확실성을 나타내는 필요한 표현은 유지했다. S1 필수 수정은 찾지 않았고, S2 편집 후보 문장 5곳을 구체적인 동사와 책임 설명으로 바꿨다. 아래 분류는 편집 판단이며 AI 여부의 확률이나 분류기 점수가 아니다.

| 패턴 | 실제 수정 전 | 실제 수정 후 |
| --- | --- | --- |
| 명사화 | 여기서 하는 일은 기사 조회 데이터의 재사용이다. | 이 경로는 조회한 기사 데이터를 재사용한다. |

| 추상 명사 중심 | 공용 캐시의 병합과 현재 화면의 응답 선택은 서로 다른 책임이다. | 공용 캐시에서 무엇을 보존할지와 현재 화면에서 어떤 응답을 쓸지를 나눠 처리한다. |

윤문 후 자연도는 A로 수동 판단했다. 추가 수정이 필요한 S1/S2를 남기지 않았다는 편집 평가이며 객관적 자연도 측정은 아니다.

수정 전 889어절, 수정 후 883어절, 변경량 근사 34어절로 **3.82%**다. frontmatter·코드 블록·링크 목적지·문장부호를 제외한 공백 어절을 SequenceMatcher로 비교했다. 형태소 분석이 아니며 자연어 의미 변경을 완벽히 세는 값도 아니다. 30% 가드 이내다.

✓ 의미 보존 검증: 6항 모두 통과.

1. 수치·날짜·고유명사: 수동 대조했고 숫자 토큰 전후 동일을 계산했다.
2. 인과관계: 늦은 GET→요약 손실, 선행 eviction→병합 근거 손실의 방향을 유지했다.
3. 부정 표현: 목록에서 생성하지 않음·새 호출 없음·현재 미실행을 유지했다.
4. 직접 인용: 외부 직접 인용을 바꾸지 않았고 코드 블록과 링크 목적지도 전후 동일하다.
5. 핵심 주장: 짧은 재사용과 본문 요약 보존 조건을 함께 설명한다.
6. 격식 수준: 한국어 기술 블로그 평서체를 유지했다.

## 미검증과 후속

cold load·새로고침·장기 메모리·여러 조건의 지연 분포, 캐시 제거 뒤 재방문, URL 변경 및 FULL_TEXT 간 충돌은 추가 검증 범위다. 기존 이동 시간의 정확한 관측 범위를 넘겨 개선율·p95로 쓰지 않았다. fixed commit 링크의 공개 접근, 블로그 source 검사·화면·CI·발행 결과는 통합 단계에서 확인해야 한다.

스킬은 개인 기여 서술을 만들지 않고 계약별 근거를 남기는 데 도움이 됐다. 개선할 부분은 브라우저 캐시의 ‘항목 제한’과 ‘전체 메모리 제한’을 구분하는 검토 항목, fixture 실행 여부를 본문과 분리해 갱신하는 절차다.

## 배치 공통 검증과 작성 담당 범위 보정

통합 담당자가 공통 검사를 별도로 실행하고 있어, 본문의 미실행 표현을 이 글의 작성 담당자가 별도로 재실행하지 않았다는 뜻으로 좁혔다. 공통 실행 결과는 통합 담당자가 확인한 범위와 함께 검증 절에 추가한다. 앞의 변경률은 humanizer 적용 단계의 전후 snapshot을 비교한 값이며 이 범위 문구 보정은 포함하지 않는다. 보정 후 원고는 같은 outputs 디렉터리의 `after-scope-review.md`에 별도 보존했다. 이 보정에서 역사 수치·명령·원문 링크를 바꾸지 않았다.
