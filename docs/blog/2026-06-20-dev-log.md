## 설계 고민 / 결정

현재 41개 article catalog는 검색 시스템 비교에는 유용하지만 title, summary,
why-it-matters 중심이라 chunking 효과를 보여주기 어렵다. 지원 과제의 키워드를
맞추기 위해 형식적인 chunking 실험을 추가하면 오히려 평가 신뢰도가 낮아진다.

그래서 실제 heading, 명령어, API 계약, 장애 대응 절차가 있는 Sigak 운영 문서를
versioned corpus로 선택했다. 정답도 chunk ID에 직접 묶지 않고 document path,
heading path, quote hash로 관리한다. 이 방식이면 chunking 전략이 바뀌어도 같은
근거를 기준으로 비교할 수 있다.

LLM judge는 자동 평가 수단으로 사용하지만 ground truth로 간주하지 않는다.
최소 18개 답변을 사람이 검토하고 disagreement를 failure artifact로 남기도록 했다.
