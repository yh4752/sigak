# 2026-10-10 개발 로그: 운영 문서 검색 평가 도구와 사람 검토 경계

## 요약

기존 서비스 전체 검사를 직접 실행하고 운영 문서 검색 평가의 준비 단계를 구현했다.
원문 근거를 chunk와 독립적으로 보존하고 fixed/heading × BM25/dense/hybrid를 비교할 수 있게 했다.
60개 질문 초안은 원문과 구조를 자동 검증했지만 사람 검토로 처리하지 않았다.
실제 AI 서버 연결 확인은 deterministic 3-query smoke로 제한했으며 전체 RAG 품질 평가를 완료했다고 주장하지 않는다.

## 설계 고민 / 결정

제품 서비스 변경 없이 실험 패키지에서 기존 FastAPI embedding 경계를 재사용했다. paid API 없이 HTTP 연결과 artifact 흐름을 검증할 수 있고, 모델 평가와 실행 연결 확인을 구분할 수 있기 때문이다.

Gold label은 chunk ID가 아니라 문서·heading·정규화한 quote·hash로 저장한다. Fixed window가 여러 heading에 걸칠 때 이웃 section의 같은 문구를 해당 heading 근거로 잘못 인정할 수 있어 chunk 안에서도 원문 section별 fragment를 보존했다.

독립 코드 검토에서 section 혼동, 전역 evidence ID 충돌, 질문 수정 뒤 stale lexical overlap, 계획과 다른 Recall 분모, smoke interval의 과도한 해석을 확인했다. 회귀 테스트를 추가하고 수정했으며 다섯 사항은 재검토에서 잔여 문제 없음으로 확인됐다. 추가로 `REVIEWED`여도 `REVISE` 질문이 있으면 full-ready로 표시하지 않도록 확인했다.

`Recall@5`는 기존 설계의 any-hit 의미를 유지한다. 중복 window 수에 따라 분모가 달라지는 conventional chunk recall과 구분하고, 전체 근거 회수 비율은 evidence coverage로 제공한다. 질문 pair를 별도 독립 표본으로 부풀리지 않도록 intent를 bootstrap 단위로 삼는다.

## 트레이드오프

- 사람 검토를 기다리는 동안 fixture 기반 검색 구현과 deterministic orchestration을 먼저 준비했다. 계획의 Checkpoint B는 착수하지 않았다.
- OpenAI 의존성, reranker, generator, LLM judge, 50개 답변 사람 검토는 후속 단계로 남겼다.
- Local multilingual 모델 다운로드나 전체 60-query 품질 평가는 실행하지 않았다. deterministic smoke는 품질 우열이나 latency benchmark 근거가 아니다.
- 개발용 결과는 ignored `outputs/rag-smoke-2026-10-10-verified/`에 보존했다. Dirty snapshot이며 최종 portfolio evidence가 아니다.
- 기존 무관한 documentation-freshness untracked 문서 두 개는 수정하지 않았다. 원격 push는 실행하지 않았다.
