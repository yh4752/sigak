# 2026-06-02 개발 로그: 검색 평가 라벨링 도구 검증과 다음 작업 정리

## 요약

오늘은 `docs/search-evaluation/labeling.html`을 새 기능으로 더 확장하지 않고, 전날 만든 라벨링 도구와 사용자 수동 검증 결과를 마무리 로그로 정리했다.
Codex의 in-app browser 자동화는 local `file://` 접근 정책으로 막혀 있었기 때문에, 자동 검증과 사용자 수동 검증을 분리해 기록했다.
검색 평가의 다음 개발 단위는 내일 진행하기로 하고, frozen catalog export 설계와 benchmark runner 구현을 다음 단계로 남겼다.

## 설계 고민 / 결정

검색 평가 도구는 이제 "만들었다"보다 "어떤 수준까지 검증했는가"가 더 중요해졌다.
그래서 사용자 수동 확인을 자동 테스트처럼 과장하지 않고, 실제 브라우저 사용 확인과 Codex가 실행한 정적 검사를 분리했다.

다음 작업은 바로 benchmark runner를 만들기보다, 먼저 API-ready article을 더 큰 frozen catalog로 export하는 설계를 잡는 쪽이 맞다.
현재 seed article 5개만으로는 Recall@5나 MRR@5 같은 수치가 포트폴리오에서 설득력 있는 검색 품질 근거가 되기 어렵기 때문이다.

## 추가 진행: API-ready article catalog export 구현 문서화

### 요약

검색 평가 라벨링 도구가 seed article 5개에 머무르지 않도록, PostgreSQL의 API-ready article을 frozen catalog JSON으로 export하는 command runner를 구현하고 로컬 smoke로 검증했다.
설계와 계획은 `docs/superpowers/specs/2026-06-02-search-catalog-export-design.md`, `docs/superpowers/plans/2026-06-02-search-catalog-export.md`를 기준으로 삼았다.
현재 catalog artifact는 `experiments/datasets/raw/articles.catalog.json`에 `catalogId=api-ready-2026-06-02`, article 6개로 생성됐다.

### 오늘 완료한 일

- `experiments/README.md`
  - raw/labels/processed dataset 디렉터리 역할, catalog export command, 옵션, 라벨링 흐름, 아직 남은 benchmark runner를 한국어로 정리했다.
- `experiments/datasets/raw/.gitkeep`, `experiments/datasets/labels/.gitkeep`, `experiments/datasets/processed/.gitkeep`
  - 생성 데이터 파일 없이도 평가 dataset 디렉터리를 Git에서 추적할 수 있게 marker를 추가했다.

  - PostgreSQL의 API-ready article 6개를 라벨링 도구 import용 frozen catalog JSON으로 생성했다.

  - catalog export command 구현과 로컬 export smoke 검증 결과를 반영했다.

### 설계 고민 / 결정

평가 dataset의 기준은 Elasticsearch, Qdrant, Neo4j projection이 아니라 PostgreSQL source of truth와 public/API-ready article boundary다.
검색 projection은 benchmark에서 비교할 대상이지, label catalog의 원천 데이터가 아니다.
그래서 catalog export 문서도 JSONL 범용 데이터셋이 아니라 `docs/search-evaluation/labeling.html`이 가져올 수 있는 catalog JSON 흐름으로 정리했다.

미검증:

- `docs/search-evaluation/labeling.html`에서 새 `articles.catalog.json`을 실제 브라우저로 import하는 단계는 아직 Codex가 자동 검증하지 못했다.
- 현재 catalog는 article 6개뿐이다. 30-50개 평가 예시는 추가 collection/source curation과 사용자 라벨링이 필요하다.
