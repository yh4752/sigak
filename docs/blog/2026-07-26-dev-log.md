# 2026-07-26 개발 로그: 재진입 문서 정비와 clean install 검증

## 요약

오랜 공백 뒤에도 Sigak을 다시 시작할 수 있도록, README·온보딩·상태·로드맵 문서를
현재 커밋 기준으로 정비했다.
문서마다 구현 상태를 반복해 적는 대신, 현재 상태는 `STATUS`, 다음 작업은 `ROADMAP`을
정본으로 두고 나머지 문서는 그곳으로 안내하게 했다.
구현된 `/research`와 `GET /api/research/overview`는 커밋된 실험 산출물을 읽는 화면으로
설명하되, smoke 규모와 2026-07-12의 미검증 환경 의존 검증은 그대로 남겼다.

문서 갱신 브랜치를 `main`에 fast-forward merge하는 과정에서 깨끗한 worktree의 `npm ci`가
실패하는 lockfile 불일치도 발견했다. lockfile을 다시 해석하고 Axios를 보안 패치
버전으로 올린 뒤, clean install과 frontend 전체 gate를 다시 통과시켰다.

## 설계 고민 / 결정

재진입 문서는 기능 목록을 또 하나의 정본으로 만들지 않는다. 실제 구현 진행은
`STATUS`, 다음 구현 순서는 `ROADMAP`에만 두고, README와 온보딩 문서는 필요한 깊이로
빠르게 이동시키는 역할을 맡긴다. 이 경계를 지켜야 기능이 바뀔 때 여러 소개 문서가
서로 다른 현재 상태를 말하는 문제를 줄일 수 있다.

`/research`는 제품 기능처럼 과장하지 않고, committed retrieval comparison,
graph-aware smoke, expanded catalog artifact를 읽는 read-only evidence view로 설명했다.
브라우저에서 실험을 실행하거나 projection을 rebuild하지 않는다는 경계도 함께 남겼다.

## 트레이드오프

문서 갱신 자체는 Markdown 범위였지만, `main` 통합에서 새 worktree를 사용하면서
lockfile 불일치를 함께 보완했다. 이로써 frontend의 clean install과 전체 gate는 새로
검증했지만, Docker가 없어서 backend 전체 gate와 runtime boot smoke는 여전히
미검증이다.

production audit은 Axios 관련 항목을 해소했지만, 최신 React Router v7에서도 RSC
advisory가 남는다. Sigak은 client-rendered Vite 앱으로 RSC·SSR runtime을 구현하지
않았지만, audit 실패를 통과로 바꾸거나 무시하지 않고 upstream 안전 버전 확인 작업으로
남긴다.
