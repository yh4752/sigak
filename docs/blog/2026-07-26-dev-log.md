## 요약

오랜 공백 뒤에도 Sigak을 다시 시작할 수 있도록, README·온보딩·상태·로드맵 문서를
현재 커밋 기준으로 정비했다.
문서마다 구현 상태를 반복해 적는 대신, 현재 상태는 `STATUS`, 다음 작업은 `ROADMAP`을
정본으로 두고 나머지 문서는 그곳으로 안내하게 했다.
구현된 `/research`와 `GET /api/research/overview`는 커밋된 실험 산출물을 읽는 화면으로
설명하되, smoke 규모와 2026-07-12의 미검증 환경 의존 검증은 그대로 남겼다.

## 설계 고민 / 결정

재진입 문서는 기능 목록을 또 하나의 정본으로 만들지 않는다. 실제 구현 진행은
`STATUS`, 다음 구현 순서는 `ROADMAP`에만 두고, README와 온보딩 문서는 필요한 깊이로
빠르게 이동시키는 역할을 맡긴다. 이 경계를 지켜야 기능이 바뀔 때 여러 소개 문서가
서로 다른 현재 상태를 말하는 문제를 줄일 수 있다.

`/research`는 제품 기능처럼 과장하지 않고, committed retrieval comparison,
graph-aware smoke, expanded catalog artifact를 읽는 read-only evidence view로 설명했다.
브라우저에서 실험을 실행하거나 projection을 rebuild하지 않는다는 경계도 함께 남겼다.

## 트레이드오프

이번에는 Markdown 문서만 바꿨다. 따라서 문서의 링크·오래된 표현·공백 오류는 다시
검사했지만, backend·frontend·AI test suite와 runtime smoke를 새로 실행하지 않았다.
2026-07-12에 기록된 `/research`의 focused test 및 frontend 전체 gate 결과와, Docker/
PostgreSQL 부재로 남은 backend 전체 gate·runtime boot smoke 미검증 상태를 새로운
성공 결과처럼 바꾸지 않았다.
