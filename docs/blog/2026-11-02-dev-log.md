# 2026-11-02 개발 로그: URL 출처 등록과 전문 재사용을 운영에 연결하기

## 요약

오전 설계에서는 고정 수집 목록과 별도 출처 DB를 통합하는 구조를 제안했다.
사용자 승인 후 구현 계획을 작성하고 DB registry·운영 명령·RSS/Atom 전문 보존·공통 HTTPS
전송을 구현해 임시 서비스에 배포했다. 토스·우아한형제들·D2를 활성화했고 기존 여섯 출처는
유지했다. 수집과 본문 준비는 무료이며, 첫 상세 요약과 기존 누적 비용 정책은 보존했다.
출처 등록 단계에는 유료 AI 요약을 요청하지 않았다. 이후 사용자가 세 출처의 실제 시험을
요청해 아래 후속 기록에 본문 누락 수정과3건의 생성·재사용·비용 관측을 추가했다.

## 설계 고민 / 결정

### URL 설정을 DB로 옮기는 것만으로는 부족했다

기존 수집 목록과 news_sources가 별도로 존재하고 저장 시 표시 이름의 slug로 출처를
찾았다. 한글 이름 충돌과 이름 변경을 피하려면 수집부터 source ID를 유지해야 했다.
설정 version을 기사 commit에서 다시 검사해 중지/설정 변경과 진행 중 수집의 경합도 막았다.
운영 probe·피드·본문은 출처별 advisory lock을 공유하지만 외부 HTTP 동안 transaction은
열지 않는다. 잠금 충돌은 SOURCE_BUSY/FETCH_BUSY로 기록하며 TRANSIENT_FETCH로 분류한다.

### 긴 피드 필드가 곧바로 전문은 아니다

토스 표본은 정규화한 피드/페이지 본문이 공유 버튼 문구 외에 일치해 AUTO 피드 경로를
승인했다. 우아한형제들은 공통 추출이 본문을 찾지 못해 `.post-content-body`를 지정하고
저자 widget을 제외했다. 피드에는 paragraph 밖의 syndication footer가 남아 CSS로 제거되지
않았으므로 PAGE를 선택했다. 실제로 제거하지 못한 문구를 제거했다고 기록하지 않는다.

D2는 서버 HTML만으로 본문을 찾지 못했다. 렌더링 페이지를 확인하고 피드 전문과 비교해
FEED_FULL로 운영했다. 첫3개 글 중 하나는 open Shadow DOM에 본문이 있었다.
정규화한 텍스트의 길이/hash가3개 모두 일치했다. 이는 기사 텍스트 확인이며 동영상 자막
수집은 아니다. 이후 링크 비중이 높은 D2 한 건은 BODY_LINK_LIST로 남겨 두었다.

### 공개 소개글을 비웠더니 검색 입력도 사라졌다

설명 없는 피드에 전문을 공개 sourceExcerpt로 넣지 않도록 명시적 빈 값을 저장했다.
그러나 ES/vector/fallback이 공개 DTO의 소개글을 입력으로 사용해 D2의 본문 단어 검색이
누락됐다. 공개 DTO와 내부 `ArticleSearchContent`를 분리해 기존1,200자 검색 범위를
유지했다. 검색 범위와 전체 요약 입력은 별개다. 이 변경은 유료 호출을 추가하지 않는다.

## 트레이드오프

DB 등록은 YAML보다 상태 관리와 이관이 필요하지만 실행 중 출처를 추가·중지할 수 있다.
URL 자동 처리에 실패하면 정확한 feed/host/root 설정을 요구한다. 모든 URL을 지원한다는
약속이나 차단 우회는 추가하지 않았다. 검증은 최소 조건이고 활성화에는 원문 표본 검토가 필요하다.
관리자 UI·범용 크롤러·arXiv PDF 전문·AI 기사 선별·커리어 전용 category/prompt는 미뤘다.

전문 피드 재사용은 추가 페이지 fetch를 줄이지만 AI 생성 시간 단축은 측정하지 않았다.
출처 등록 단계의 표본 검사만으로는 새 출처의 AI 요약 품질을 확인하지 못했다.
이후 실제3건을 시험했지만 더 넓은 품질·지연시간 분포는 여전히 미검증이다.
기존 한도는 총5달러, 앱4달러 중단·총200회/일20회·회당0.02달러 영구 보수 차감이다.
UNKNOWN은 재시도하거나 환급하지 않는다.

## 실제 AI 3건 후속 검증

### 요약과 결정

사용자가 토스·우아한형제들·D2 기사 각1건을 실제로 요약하고 본문·시간·비용을 확인해 달라고
요청했다. 호출 전에 저장 본문과 렌더링 원문을 대조했고 토스에서 핵심 목록 누락을 발견했다.
피드와 페이지 양쪽에 같은 추출기를 썼기 때문에 이전 feed/page 비교는 이 누락을 찾지 못했다.
원문 DOM과의 별도 대조가 필요한 이유다.

토스는 강조 상자를 aside로 표현한다. 공통 clean이 aside를 전부 지우면서3개 처리 규칙과
2개 평가 기준까지 삭제했다. `ArticleBodyExtractor.kt`는 aside 태그만으로 지우는 규칙을
제거했고 알려진 widget·출처별 제외 설정은 유지했다. 기존 관련 카드 테스트에는 post-card
class를 명시하고 PAGE/FEED에서 강조 목록 보존을 검증하는 회귀를 먼저 실패시켰다.
`FullTextStore.kt`는 추출 version을 registry-body-v2로 기록한다.

요약 요청이 없는 토스20건을 백업하고, 검증한 JAR의 실제 Java 추출기로 기존 raw feed를
재추출했다.13건의 텍스트가 변경됐으며, 기사 행 잠금·이전 hash·requested_summary=false·
유료 job 없음 조건을 검사한 transaction으로 반영했다. 기존 summary/history/budget는
수정하지 않았다. 시험할 토스218은5956→6168자로 복구됐고 원문과 정규화 전체 텍스트가 일치했다.

### 본문과 실제 요약

우아한형제들221은 본문 안의 코드16개와 마지막 문단을 확인했고, D2226은 Shadow DOM의
본문과 코드7개를 대조했다. 토스218도 별도 본문 root로 비교해 댓글/공유 UI를 제외했다.
세 본문 모두 공백 제거 후 전체 길이·fingerprint가 렌더링 원문과 일치했다. 이후 공개 서비스의
`POST /api/articles/{id}/summary`로 각각 한 번만 생성하고 GET으로500ms 간격 확인했다.
일반 HTTP 지연이 더해지므로 실제 폴링 간격은500ms보다 길 수 있다.

| 출처/기사 ID | 저장 본문 문자 수 | 본문 경로 | 공개 요청→READY | 공개 저장 결과 재요청 | dispatch 후 처리 | 입력/출력 token | token 추정 USD |
| --- | ---: | --- | ---: | ---: | ---: | ---: | ---: |
| 토스218 | 6168 | FEED | 8.047s | 0.274s | 7.787s | 3634/440 | $0.001255 |
| 우아한형제들221 | 16836 | PAGE | 6.623s | 0.085s | 6.216s | 8534/399 | $0.002186 |
| D2226 | 17455 | FEED | 6.674s | 0.073s | 6.107s | 9228/380 | $0.002302 |

- 세 건 모두 gpt-5.6-luna, FULL_TEXT, READY, truncated=false, cacheWriteTokens=0이다.
- DB request_json의 rawContent가 저장된 전체 본문과 정확히 일치했고 근거9개 모두 본문에 있다.
- queue는 각각41/30/13ms였다. dispatch 후 처리시간에는 private AI 호출·검증·저장 경계가 포함된다.
- 본문은 요청 전에 준비돼 클릭 시 추가 본문 fetch는 없었다. 우아한형제들의 기존 배경 fetch는
  890ms였다. FEED의 fetch_duration_ms=0은 기사 페이지 추가 fetch가 없다는 뜻이며 피드
  수집의 네트워크 시간이0이라는 뜻이 아니다.
