# 2026-07-12 개발 로그: `/research` 포트폴리오 evidence dashboard 구현

## 요약

오늘은 Sigak의 초기 `/research` dashboard를 구현했다.
목표는 예쁜 차트 페이지가 아니라, 취업 포트폴리오에서 보여줄 수 있는 검증 근거를 제품 안에서 확인하게 만드는 것이었다.
Spring Boot가 커밋된 retrieval/graph/catalog artifact를 읽어 `GET /api/research/overview`로 제공하고, React는 Zod 검증 후 `/research` 화면에 retrieval 비교, graph-aware smoke evidence, expanded catalog 상태, limitation을 표시한다.
전체 backend gate와 runtime API smoke는 로컬 Docker/PostgreSQL이 꺼져 있어 완료하지 못했고, 그 사실을 미검증으로 남긴다.

## 설계 고민 / 결정

Frontend가 `experiments/` JSON 파일을 직접 읽지 않고 Spring Boot의 `GET /api/research/overview`만 호출하도록 했다.
Sigak의 원칙은 frontend가 Spring Boot만 바라보는 것이고, 포트폴리오에서도 "실험 artifact -> backend DTO -> Zod 검증 -> UI" 흐름이 더 설득력 있다.

또 하나의 결정은 graph query evidence의 `reasonCoverage`를 nullable로 유지한 것이다.
실제 `graph-context.metrics.by-query.json`에는 `postgres vector search` 항목의 `reasonCoverage`가 `null`로 들어 있다.
이를 0%로 바꾸면 "적용 불가"와 "성과 없음"이 섞이므로, backend DTO와 frontend Zod schema에서 `null`을 허용하고 UI에서는 `n/a`로 표시하게 했다.

## 트레이드오프

얻은 것:

- `/research`가 실제 retrieval/graph/catalog artifact를 읽는 제품 화면이 되었다.
- artifact가 없거나 깨져도 section 단위로 unavailable 상태를 보여주므로 dashboard 전체가 깨지지 않는다.
- smoke-only warning과 reviewed label 부족 상태를 화면과 문서에 숨기지 않는다.

미룬 것:

- RAG evaluation, failure case, token/cost section은 아직 artifact가 없으므로 구현하지 않았다.
- chart library는 도입하지 않았다. 이번 버전은 table, metric panel, limitation panel로 충분히 읽히게 만들었다.
- Docker/PostgreSQL이 내려간 상태라 runtime API smoke와 실제 브라우저 visual smoke는 완료하지 못했다.
