# 2026-06-10 개발 로그: 코드베이스 전체 정리 문서 + 보수적 리팩토링

## 요약

backend/frontend/ai 전체 소스를 읽고 구조·책임·핵심 흐름을 정리한 `docs/CODEBASE_OVERVIEW.md`를 새로 작성했다.
동작 변경 없는 보수적 리팩토링만 적용했다: 중복 코드 통합(collector의 `atomLink`, 검색 서비스의 `runCatchingMeasured`, 메트릭 recorder의 percentile/윈도우), 불필요한 override·한 줄 wrapper 제거, dead code 제거.
frontend와 AI 서버는 테스트로 검증했고, backend는 실행 환경 제약(JDK 17/Docker 부재)으로 미검증이다.

## 오늘 완료한 일

- `docs/CODEBASE_OVERVIEW.md` (신규)
  - 서비스별 패키지 책임 표, 공개 검색·수집 파이프라인·projection rebuild 흐름, 적용한 리팩토링과 남은 리팩토링 후보를 정리했다.
- backend 보수적 리팩토링
  - `collection/collector/XmlText.kt`: 두 collector에 중복이던 `Element.atomLink()`를 공용 확장 함수로 이동 (`ArxivCollector.kt`, `RssAtomCollector.kt`에서 제거).
  - `common/time/ElapsedMeasurement.kt`: `MeasuredAttempt` + `runCatchingMeasured` 추가, `search/hybrid/ArticleRetrievalCandidateService.kt`와 `ArticleVectorCandidateSearchService.kt`의 private 중복(`SearchAttempt`) 제거.
  - `common/metrics/RecentObservationWindow.kt` (신규): 최근 관측 윈도우 + `percentileOf` 공통화, `search/metrics/ArticleSearchMetricsRecorder.kt`와 `search/vector/ArticleVectorSearchMetricsRecorder.kt`의 중복 제거.
  - `search/service/ElasticsearchArticleKeywordSearchService.kt`: 인터페이스 default와 동일한 `searchArticleIds(query)` override 제거.
  - `collection/service/ArticleNormalizer.kt`, `CollectedArticlePersistenceService.kt`: `PublishedAtParser`를 감싸기만 하던 한 줄 wrapper 인라인.
  - `search/graph/Neo4jArticleGraphProjectionIndexer.kt`: 수동 try/finally 세션 관리를 `driver.session().use(block)`로 단순화.
- frontend 리팩토링
  - `src/api/articles.ts`: 목록 요청 + Zod 검증을 `requestArticleList()`로 추출.
  - `src/pages/HomePage.tsx`: useEffect의 async wrapper에 유지 이유 주석 추가 (아래 검증 항목 참고).
- ai 리팩토링
  - `app/services/deterministic_embedding_service.py`: 어디서도 사용하지 않는 module-level `embed_text()` 제거 (router는 `build_embedding_response` 사용).

## 설계 고민 / 결정

리팩토링 강도는 의도적으로 보수적으로 잡았다. 사용자가 "동작 변경 없는 정리"를 선택했고, backend 테스트를 이 세션 환경에서 실행할 수 없었기 때문에 공개 API 시그니처와 빈 구성을 바꾸지 않는 변경만 적용했다.
`CollectionStatus`/`ProcessingStatus` enum 중복, CLI runner 패턴 중복 같은 구조적 변경은 적용하지 않고 `CODEBASE_OVERVIEW.md`의 후보 목록으로만 남겼다.
metrics recorder의 `@Synchronized` 블록은 `RecentObservationWindow` 내부로 이동했다. `summarize()`는 이전에도 deque를 복사한 뒤 계산했으므로 동시성 동작은 동일하다.

## 트레이드오프

- 얻은 것: 동일 로직 3쌍(중복 6곳)이 공용 모듈로 합쳐져 이후 검색/수집 코드를 수정할 때 한 곳만 고치면 된다.
- 시도 후 되돌린 것: `HomePage.tsx`의 useEffect async wrapper 제거는 `npm run lint`에서 `react-hooks/set-state-in-effect` 오류를 일으켜 원복하고, 대신 유지 이유를 주석으로 남겼다.
- 미룬 것: 구조적 리팩토링 후보 7건 (`docs/CODEBASE_OVERVIEW.md` 6절).

## 검증

이 세션은 Linux 샌드박스에서 실행되어 backend 도구 체인(JDK 17, Docker/Testcontainers)을 사용할 수 없었다. frontend는 lockfile 호환성 때문에 소스 사본에서 `npm install` 후 실행했다.

| 영역 | 실행한 명령 | 결과 |
| --- | --- | --- |
| ai | `python3 -m pytest -q` (ai/) | 8 passed |
| frontend | `npm test` | 6 files, 33 passed |
| frontend | `npm run lint` | 통과 (오류 0) |
| frontend | `npm run build` | 성공 (tsc -b && vite build) |
| backend | `./gradlew test`, `./gradlew check` | **미검증** — 로컬에서 실행 필요 |

backend 변경은 git diff를 수동 리뷰했다(시그니처/동작 보존 확인). 다음 세션 또는 로컬에서 `cd backend && ./gradlew test && ./gradlew check`를 반드시 실행해야 한다.
