# 0006: 운영 출처를 PostgreSQL에 등록하고 검증 후 활성화한다

## 상태

Proposed — 2026-11-02 설계 초안. 구현과 운영 전환은 미완이다.

## 배경

수집 출처가 Kotlin 목록에 고정되어 있고 `news_sources`는 별도로 만들어진다.
출처를 추가할 때 수집 registry와 본문 host/selector 코드를 함께 바꿔야 한다.
사용자는 URL 등록으로 출처를 추가·변경할 수 있는 구조를 요청했다.

## 결정 제안

- 기존 PostgreSQL `news_sources`를 운영 registry 정본으로 확장한다.
- 고정 source ID를 수집부터 저장까지 전달하고 표시 이름에서 식별자를 만들지 않는다.
- 블로그/RSS/Atom URL 등록, 무료 표본 검증, 활성화·중지 기능을 운영 명령으로 제공한다.
- 코드에는 형식별 수집기·공통 본문 추출을 두고 출처별 selector/허용 host는 데이터로 관리한다.
- 등록 URL도 공통 외부 요청 정책을 거치며, feed 필드 이름만으로 전문이라고 판단하지 않는다.
- Spring이 수집·저장·요약 요청을 조정하고 private FastAPI의 기존 유료 boundary를 재사용한다.

## 대안과 트레이드오프

YAML은 단순하지만 재시작·DB 동기화 부담이 남는다. DB 방식은 이관과 검증 상태 관리가
필요한 대신 재배포 없이 등록·중지할 수 있다. 관리자 웹 화면은 인증과 UI 범위를 늘리므로
미룬다. 범용 크롤러나 AI 기반 추출도 도입하지 않는다.

기계 검사만으로 모든 문서의 완전성을 증명할 수 없으므로 활성화 전에 원문 표본을 확인한다.
새 출처가 기존 요약을 재생성하거나 누적 비용을 초기화하지 않게 한다.

## 영향

기존 article/source FK와 저장된 요약·비용을 유지하는 명시적 migration이 필요하다.
자동 수집은 DB 활성 출처를 회차마다 읽는다. 공개 API와 프록시 허용 경로는 바꾸지 않는다.
기존 출처의 중지와 새 후보의 활성화는 설계 문서 작성만으로 실행하지 않는다.

세부 계약과 검증 기준은 [출처 등록 설계](../superpowers/specs/2026-11-02-url-source-registration-design.md)에 둔다.
